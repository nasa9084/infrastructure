* Kubernetes (home k0s cluster)

Manifests for the single-node k0s cluster running on the home Proxmox (VM =kubernetes=).

** Layout

| Path                   | What                                                          |
|------------------------+---------------------------------------------------------------|
| =stacks/<name>/*.yaml= | Applied automatically by the k0s Manifest Deployer (see below) |
| =runbooks/=            | Manifests for manual procedures. *Never* put these in =stacks/= |
| =sync/=                | Script and systemd units that pull =stacks/= onto the VM       |

** How a change reaches the cluster

1. Merge a PR that changes =kubernetes/stacks/=.
2. A systemd timer on the VM runs =sync/k0s-manifest-sync.sh= every 5 minutes. It downloads this repo as a tarball (public repo, no auth) and copies each =stacks/<name>/= into =/var/lib/k0s/manifests/<name>/=.
3. The [[https://docs.k0sproject.io/stable/manifests/][k0s Manifest Deployer]] watches that directory, applies the manifests, and *prunes* the resources of any file that is removed.

The script only touches stacks it created itself (tracked in =/var/lib/k0s-manifest-sync/managed=), so the stacks managed by k0s (=calico=, =coredns=, ...) are never modified.

** Rules for a stack

- Only files ending in =.yaml= are read (=.yml= is ignored). Sub-directories inside a stack are ignored.
- Always set =metadata.namespace= explicitly; the deployer has no default namespace.
- *Do not put a =Namespace= object in a stack.* Removing the file would prune the namespace together with the Secrets that were created by hand.
- *No Secrets in Git.* Create namespaces and Secrets by hand (below).
- Keep resource requests small. The node has 1 vCPU and about 2.2GB of RAM.
- Removing a file deletes its resources. hostPath data is not deleted.

** Namespaces and Secrets (by hand)

Run on the k0s VM. Values are typed interactively so they stay out of the shell history.

#+begin_src sh
sudo k0s kubectl create namespace victoria-metrics

read -rsp 'R2 Access Key ID: ' K; echo
read -rsp 'R2 Secret Access Key: ' S; echo
sudo k0s kubectl -n victoria-metrics create secret generic r2-credentials \
  --from-literal=AWS_ACCESS_KEY_ID="$K" \
  --from-literal=AWS_SECRET_ACCESS_KEY="$S"
unset K S

read -rsp 'HA long-lived token: ' T; echo
sudo k0s kubectl -n victoria-metrics create secret generic ha-token \
  --from-literal=token="$T"
unset T

# grafana-pdc: copy the 'kubectl create secret' command shown on the PDC page
# of Grafana Cloud and add '-n grafana-pdc' to it
sudo k0s kubectl create namespace grafana-pdc
#+end_src

The R2 bucket =prometheus-remote-store= is managed in [[../cloudflare/r2.tf][cloudflare/r2.tf]]. The S3-compatible key is an account API token scoped to that bucket (Object Read & Write, no TTL), created in the Cloudflare dashboard.

** Installing the sync on the VM

The VM has no git or rsync; the script only needs =curl=, =tar=, =cmp= and =find=.

#+begin_src sh
base=https://raw.githubusercontent.com/nasa9084/infrastructure/main/kubernetes/sync
sudo curl -fsSL "$base/k0s-manifest-sync.sh" -o /usr/local/sbin/k0s-manifest-sync.sh
sudo chmod 0755 /usr/local/sbin/k0s-manifest-sync.sh
sudo curl -fsSL "$base/k0s-manifest-sync.service" -o /etc/systemd/system/k0s-manifest-sync.service
sudo curl -fsSL "$base/k0s-manifest-sync.timer" -o /etc/systemd/system/k0s-manifest-sync.timer
sudo systemctl daemon-reload
sudo /usr/local/sbin/k0s-manifest-sync.sh      # first run by hand
sudo systemctl enable --now k0s-manifest-sync.timer
#+end_src

The script and units are not updated by the sync itself; re-run the =curl= lines when they change.

** Runbooks

*** Restore drill (does not touch production)

Restores the latest R2 backup into a scratch directory and compares it with production.

#+begin_src sh
raw=https://raw.githubusercontent.com/nasa9084/infrastructure/main/kubernetes/runbooks
sudo k0s kubectl apply -f "$raw/vmrestore-test-job.yaml"
sudo k0s kubectl -n victoria-metrics wait --for=condition=complete job/vmrestore-test --timeout=120s
sudo k0s kubectl apply -f "$raw/vmrestore-verify-pod.yaml"
# compare the series count of the pod IP with production
curl -s http://<vm-restore-verify pod IP>:8428/api/v1/series/count
curl -s http://<victoria-metrics pod IP>:8428/api/v1/series/count
# clean up
sudo k0s kubectl -n victoria-metrics delete pod/vm-restore-verify job/vmrestore-test
sudo rm -rf /var/lib/vm-restore-test
#+end_src

Result of the first drill (2026-10-15): 513,393 bytes restored in about 2 seconds, 2515 series on both sides.

*** Restoring production

The Manifest Deployer may re-apply a stack and undo a manual =scale= or =suspend=, so take the stack out of the deployer first. This has not been rehearsed yet; check it on the first real use.

1. =sudo systemctl stop k0s-manifest-sync.timer=
2. Remove =/var/lib/k0s/manifests/victoria-metrics= (the deployer prunes the Deployment and the CronJob; the hostPath data stays).
3. Empty =/var/lib/victoria-metrics= and run a copy of =runbooks/vmrestore-test-job.yaml= whose =-storageDataPath= volume points at =/var/lib/victoria-metrics=.
4. =sudo systemctl start k0s-manifest-sync.timer= (or run the script by hand) to bring the stack back.

** Notes
